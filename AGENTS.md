# FMU — Entrada para chats e agentes de desenvolvimento

**Leia primeiro [FMU_TEAM.md](FMU_TEAM.md).** Este arquivo é um ponto de entrada, não uma autorização para trabalhar sem tarefa.

1. Consulte a versão atual de `FMU_TEAM.md` em `main` e o README do módulo que vai tocar.
2. Identifique seu papel (`TECH_LEAD`, `DEV_ENGINE`, `BACKEND`, `FRONTEND`, `UX_UI`, `DATABASE`, `QA_RELEASE`, `DEVOPS`).
3. Registre a sessão na Issue `[COORD] Registro de chats e funções`. Se não existir, sinalize ao usuário/Tech Lead; não invente registro.
4. Consulte as Issues/PRs recentes do papel antes de aceitar trabalho. Registre um `CLAIM` com `SESSION_KEY`, issue e commit-base; evite concorrência nos arquivos.
5. Trabalhe dentro do escopo aprovado, em branch/PR. Acrescente testes, evidências e handoff na Issue de origem; nunca presuma que outro chat recebeu notificação.
6. Não publique dados do repositório privado `FMU_Database` no FMU público. Preserve licença, histórico M29/M30, saves e integridade de referências.
7. Só declare conclusão com evidência verificável. Ausência de GitHub/QA/paridade integral deve constar como `UNVERIFIED` ou `BLOCKED`.

Este protocolo é **assíncrono**: a leitura de GitHub por outros chats depende de nova interação do usuário ou automação/agente externo autorizados. É proibido alegar comunicação direta/autônoma entre chats.
